本章概述使用 SnapCenter 進行備份、還原和恢復、SAP 系統重新整理和非同步複寫作業。



[[backup-operations]]
== 備份作業

備份操作的執行方式與 https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-backup-operations.html["在SnapCenter中了解 SAP HANA 快照的備份作業"]中所述相同。


NOTE: 如果儲存單元未設定一致性群組，SnapCenter 會在首次 Snapshot 快照技術備份作業時建立一致性群組和子一致性群組。然後，HANA 資料儲存設備將指派至該子一致性群組。SnapCenter Snapshot 快照技術備份將列於該子一致性群組中。

== 還原與還原

還原與恢復作業的執行方式與所述相同 https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-restore.html["使用SnapCenter恢復 SAP HANA 資料庫"]。



[[asynchronous-storage-replication]]
== 非同步儲存設備複寫

已為 HANA 資料 Volume 設定非同步儲存複寫。

image:hana-sc-bare-metal-asar2-image-009.png["寬度=601，高度=180"]

複寫已根據 MirrorAndVault 原則進行設定。

image:hana-sc-bare-metal-asar2-image-010.png["width=601,height=206"]

此 MirrorAndVault 原則包含不同的 SnapMirror 標籤和保留期限。

image:hana-sc-bare-metal-asar2-image-011.png["width=601,height=235"]

在 SnapCenter 中，已設定一項原則來比對 ONTAP MirrorAndVault 原則的 SnapMirror 標籤「daily」。

image:hana-sc-bare-metal-asar2-image-012.png["width=378,height=354"]

使用 ONTAP MirrorAndVault 原則時，即使 Snapshot 快照技術備份在目標儲存設備中僅可用一次，SnapCenter 也會顯示分隔的 Vault 和 Mirror 複本。

image:hana-sc-bare-metal-asar2-image-013.png["寬度=601，高度=294"]

[[snapcenter-workflow]]
=== SnapCenter 工作流程

操作詳情和先決條件請參閱 https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-hana-sys-refresh-with-sc.html#prerequisites-and-limitations["SAP HANA系統更新SnapCenter 功能"]。具體而言，必須先將目標系統新增至 SnapCenter，才能執行第一次重新整理/複製操作。

複製工作流程的第一步是提供目標主機和目標 SID。

image:hana-sc-bare-metal-asar2-image-014.png["width=333,height=313"]

協定選擇必須為「FCP」。

image:hana-sc-bare-metal-asar2-image-015.png["width=334,height=312"]

您也可以選擇新增 sc-system-refresh.sh 指令碼來自動化恢復操作。

image:hana-sc-bare-metal-asar2-image-016.png["width=352,height=331"]

下方快照顯示複製工作流程的作業日誌。

image:hana-sc-bare-metal-asar2-image-017.png["width=379,height=468"]
